# Font Sync

Figma desktop plugin plus a per-machine helper that installs fonts from a shared Google Drive folder
(`font-sync-figma-plugin`), published to npm as `figma-font-sync` for any team with its own Google OAuth
client. Design and the evidence behind it: `docs/architecture.md`. Packaging: `docs/distribution.md`.

## Layout

| Path | What lives there |
|---|---|
| `apps/helper/src/api` | Hono OpenAPI app: `routes.ts` + `schemas.ts` are the contract; `app.ts` wires handlers and middleware; `pairing.ts` |
| `apps/helper/src/cli` | `setup`, `start`/`stop`, `doctor`, `uninstall` support: runtime copy in `<dataDir>/bin`, plugin files, pid file and `/health` probe |
| `apps/helper/src/google` | Desktop OAuth (loopback + PKCE) and the Drive v3 REST client |
| `apps/helper/src/library` | Library folder logic: discovery, listing, shared face index, resolve, install, upload, remove |
| `apps/helper/src/fonts` | sfnt parser, Figma `{family, style}` matching, local font scan |
| `apps/helper/src/install` | Per-OS font install and uninstall |
| `apps/helper/src/config` | Per-OS paths, atomic JSON files, secret store, Google client resolution |
| `apps/helper/src/service` | Start-at-login registration |
| `apps/helper/scripts` | `build.ts` (binaries, plugin embedded), `pack-npm.ts` (npm package dirs), `openapi.ts` |
| `apps/helper/openapi.json` | Generated from `routes.ts`; input for the plugin client. Commit it |
| `apps/plugin/src/main` | Figma main thread: scan text nodes, clientStorage, selection |
| `apps/plugin/src/ui` | React UI iframe. `src/ui/api` is generated by Hey API and gitignored |
| `apps/plugin/src/shared/messages.ts` | The main thread and UI message protocol |
| `packaging/` | `install.sh` (the curl installer, served by unpkg from the main package) and the npm launcher `npm/bin/figma-font-sync.js` |
| `testing/guard.ts` | Test preload that blocks the real keychain, launchd, registry and Google (see invariant 15) |
| `.github/workflows` | `ci.yml` on PRs; `release.yml` publishes to npm on a `v*` tag |
| `docs/distribution.md` | npm packages, binaries, on-disk layout, CLI, install.sh: the decisions and why |
| `docs/releasing.md` | Maintainer steps: versioning, npm bootstrap, release, verify, roll back |

## Invariants

1. **Font identity is Figma's `{family, style}`**, computed as family = name ID 16 else 1, style = name ID 17
   else 2, one style per `fvar` named instance. The Plugin API has no PostScript name, so any other rule
   produces false "missing" results.
2. **The helper binds only `127.0.0.1` and `::1`, checks the Host header, and requires the pairing bearer
   token on every route except `/health`, `/pair/start`, `/pair/complete` and the `/pair` page.** Plugin
   requests carry `Origin: null`, which any web page can also send.
3. **The `/pair` HTML page never gets CORS headers.** It shows the pairing code; a readable response would
   let any plugin pair itself.
4. **The plugin calls `http://localhost:47321`, never `127.0.0.1`.** Figma's manifest validator rejects
   IP literals, and the CSP it builds blocks anything not listed. Changing the port means changing
   `manifest.json` too.
5. **Google tokens never leave the helper.** The plugin holds only the pairing token, in `figma.clientStorage`.
6. **Installed font files are never overwritten.** Names carry the md5 prefix; Windows locks loaded fonts.
7. **Names from Drive never become paths or shell arguments.** Install file names come from
   `installFileName()`; Windows PowerShell gets data through environment variables.
8. **Permissions are Drive capabilities read at runtime** (`canAddChildren`, `canTrash`, `canRemoveChildren`),
   not inferred from a role name.
9. **`openapi.json` is generated, the plugin client is generated.** Edit `routes.ts`/`schemas.ts`, then `bun run gen`.
10. **TypeScript stays on 6.x** until `@hey-api/openapi-ts` supports TypeScript 7: it imports the JS compiler API that 7 removed.
11. **Public builds never contain a Google client.** `FONT_SYNC_PUBLIC_BUILD=1` fails the build when
    `FONT_SYNC_GOOGLE_CLIENT_ID` or `_SECRET` is set, and the release workflow always sets it. Anyone can
    read strings out of an npm binary; teams bring their own client through `setup` (config.json) or the env.
12. **The background helper runs from `<dataDir>/bin`, never from `node_modules`.** pnpm's global path is
    versioned and Windows refuses to replace a running .exe, so `npm i -g` would fail with EBUSY or leave
    start-at-login pointing at a deleted file.
13. **Plugin files are embedded in the binary and rewritten to `<dataDir>/figma-plugin` when `.version`
    differs.** Figma reads development plugins from the path the user imported, so that path must survive
    upgrades while its contents follow the binary.
14. **The CLI is `figma-font-sync`.** The npm launcher, `install.sh` and the plugin's "not running" screen
    all use that name. Data dirs, the keychain service and the LaunchAgent label keep `font-sync`;
    renaming them strands existing installs.
15. **Tests never reach the real machine.** The Google sign-in lives in the real OS keychain and launchd is
    per user, so a temp `HOME` isolates neither. `testing/guard.ts` is preloaded by every `bunfig.toml`:
    it points HOME and `os.homedir()` at a temp dir and makes `Bun.secrets`, launchctl/systemctl/reg/
    PowerShell and Google hosts throw. A test once ran the CLI with real dependencies and rewrote the
    developer's LaunchAgent. Smoke runs outside `bun test` must never call `logout`, `uninstall --purge`
    or `autostart enable`.

## Commands

```bash
bun install
bun run gen          # openapi.json from routes.ts, then the plugin client
bun run typecheck
bun test
bun run --cwd apps/helper dev          # helper on localhost:47321 with reload
bun run --cwd apps/plugin dev          # rebuild plugin on change; import apps/plugin/manifest.json in Figma desktop
bun run build        # private: binaries in apps/helper/dist carry the apps/helper/.env client; never pack or publish them
bun run pack:npm     # gen, plugin build, public build (no Google client), npm package dirs in apps/helper/dist/npm
FONT_SYNC_PUBLIC_BUILD=1 FONT_SYNC_TARGETS=bun-darwin-arm64 bun --no-env-file apps/helper/scripts/build.ts
bun apps/helper/scripts/pack-npm.ts --partial    # local smoke test of one platform; needs the plugin built first
```

The helper needs a Google "Desktop app" OAuth client. Bun loads `FONT_SYNC_GOOGLE_CLIENT_ID` and
`_SECRET` from `apps/helper/.env` for anything run from `apps/helper`. To save them in your real
config.json once, so the CLI works from any directory, build the plugin (setup copies its files) and run
from `apps/helper`:

```bash
bun src/main.ts setup --client-id <id from .env> --client-secret <secret from .env> --no-autostart
```

`--no-autostart` keeps start at login from running the repo copy, which would hold port 47321 while you
use `dev`.

Google Cloud setup is in `README.md`, which is also the public npm page. Releasing: `docs/releasing.md`.
